# 自定义指令（Custom Instructions）使用指南

后台 → AI Moderation → **自定义指令** 是扩展为你预留的"补充规则"入口。本指南说明它的原理、写法、三档严格程度示例，以及验证方法。

---

## 一、原理：这个字段是怎么起作用的

扩展发送给 AI 的请求包含两条消息：

```
system: 内置审核提示词
        + "\n\n补充审核要求：\n"
        + 【你填写的自定义指令】
user:   待审核的用户内容
```

也就是说，你填写的内容会被**追加到内置提示词之后**，共同构成完整的审核规则。模型根据 system 指令来判定 user 内容。

两个关键点：

1. **后写的指令权重更高**：对大模型而言，出现在后面的指令通常执行优先级更高。所以自定义指令可以：
   - 加强某个类别的审核力度（如"凡是出现微信号一律违规"）；
   - 增加内置规则没有的社区专属规则；
   - 调整整体判定倾向（宽松 / 严格）。
2. **不能改变输出格式**：扩展要求模型必须返回 JSON（`{"compliant": ...}`），自定义指令不能要求模型"直接回答是或否"或输出其他格式，否则扩展无法解析结果（会按"AI 服务异常"处理，默认放行）。

---

## 二、填写说明（写作要点）

1. **一条规则一行**，或用分号/编号分隔；规则之间不要互相矛盾。
2. **用明确的动词**：`禁止`、`必须`、`一律判定为违规`、`应当判定为合规`。避免"适当""尽量""酌情"这类模糊词。
3. **给出可判定的标准**：说明什么算、什么不算。例如：
   - ❌ 模糊："打击不良内容"
   - ✅ 具体："禁止发布微信号、QQ 号、二维码等联系方式用于引流"
4. **必要时写明豁免场景**，避免误杀：
   - ✅ "新闻报道、科普、求助、举报语境下提及敏感词，仍判定为合规"
5. **与内置规则冲突时，注明优先级**：
   - ✅ "以下规则与本扩展内置规则不一致时，以本规则为准"
6. **只写审核相关的内容**：无关指令会浪费 token，还可能引入偏差。
7. **先小步测试再上线**：填好后用 `php flarum ai-moderation:check "..."` 验证效果（见第五节）。

## 三、不同严格程度的示例（可直接复制粘贴）

### 档位一：宽松模式 —— 只拦截最严重的违法内容

```text
请以最宽松的标准审核，仅拦截以下内容：
1. 涉及未成年人的色情内容；
2. 明确组织、教唆诈骗、毒品、赌博等违法行为的指令；
3. 危害国家安全的明确煽动。
除此之外，一般性骂人、擦边、广告、个人纠纷等，只要没有明确违法或严重伤害他人，一律判定为合规（compliant: true）。
```

适用场景：社区刚起步、希望降低发帖门槛、人工审核兜底。

### 档位二：标准模式 —— 默认规则 + 社区专属规则（推荐）

```text
以下为本社区补充规则，请严格执行：
1. 禁止任何形式的广告引流：包括微信号、QQ 号、二维码、外链、公众号推广、拉群等；
2. 禁止索要或交换联系方式用于线下交易或约见；
3. 新闻报道、科普、求助、举报语境下提及敏感词，仍判定为合规；
4. 允许适度的吐槽与批评，但禁止对个人或群体进行侮辱性攻击（含谐音、拼音、缩写、拆字等一切规避形式）；
5. 判定有疑问时，以最接近的明确规则为准，不要自行扩大范围。
```

适用场景：大多数社区默认选择，平衡审核力度与用户体验。

### 档位三：严格模式 —— 宁可误杀，不可放过

```text
请以最严格的标准审核，宁可误杀不可放过：
1. 任何侮辱、贬损、攻击性表达（含谐音、拼音、缩写、拆字、异体字、外语、符号变形等一切规避形式）一律判定为违规；
2. 任何涉及赌博、色情、诈骗、毒品、暴力的暗示、隐晦表达或擦边内容，一律判定为违规，即使没有直接字眼；
3. 任何广告、引流、联系方式推广，一律判定为违规；
4. 政治敏感或争议性话题，即使措辞中性，也判定为违规（违规类别填"政治敏感"）；
5. 只要存在一丁点违规可能性，就判定为违规（compliant: false），并在 reason 中说明疑点；
6. 仅当内容完全无害、明确合规时才判定为合规。
```

适用场景：监管压力大、内容安全优先、接受较高误杀率的社区。

## 四、三档判定差异示例

| 用户内容 | 宽松 | 标准 | 严格 |
|---|---|---|---|
| 正常技术讨论："聊聊数据库优化" | 合规 | 合规 | 合规 |
| "你们学校就是个垃圾" | 合规（一般骂人） | 违规（侮辱） | 违规 |
| "你们学校就是个辣鸡"（谐音） | 合规 | 违规 | 违规 |
| "加我微信领红包" | 合规 | 违规（广告） | 违规 |
| "根据报道，警方捣毁赌博窝点" | 合规 | 合规 | 视规则①是否豁免（严格档默认较易误判，可加"新闻科普豁免"子句） |
| "晚上约p吗"（擦边） | 合规 | 违规 | 违规 |

> 严格模式的误杀率显著更高（例如把批评、争议、黑色幽默都拦下），建议先用宽松/标准档运行几天，观察真实误报后再逐步收紧。

## 五、验证方法

修改自定义指令后，用 CLI 直接测试（无需发真实帖子）：

```bash
php flarum ai-moderation:check "你们学校就是个垃圾"
php flarum ai-moderation:check "你们学校就是个ラジ"     # 片假名替换
php flarum ai-moderation:check "加我微信领红包"
php flarum ai-moderation:check "根据报道，警方捣毁赌博窝点"   # 应合规
```

`ai-moderation:check` 会打印判定 JSON 和结果；`ai-moderation:test` 可确认连接正常。

## 六、注意事项

1. **严格模式会明显提高误杀率**，这是预期行为；若误杀过多，在规则里补充豁免条款即可。
2. **输出格式不可变**：自定义指令必须允许模型返回 JSON。
3. **模型速度影响体验**：推理型模型（如 mimo-v2.5）单次审核可能超过 20 秒，请相应调大"请求超时（秒）"，或换用更快的模型；审核是同步的，发帖时用户会等待。
4. **内置提示词已覆盖**：识别谐音、片假名、拼音、拆字等规避手段，内置提示词已有要求；自定义指令用于**加强或定制**，而不是从零补齐。

## 七、实测结果（小米 MiMo mimo-v2.5）

> 测试环境：Flarum 1.8.12 / PHP 7.4.33，AI 来源 `https://api.xiaomimimo.com/v1`（`mimo-v2.5`），temperature=0，默认内置提示词。共 27 个用例：明确违规 7 + 规避变体 13 + 合规语境 5 + 政治敏感（合成）1。

### 默认档第 1 轮：27/27 全部正确

| 类别 | 用例（节选） | 判定 |

| 诈骗刷单 | 加我QQ，教你刷单赚钱，先交押金 | 违规（违法活动） |

**结论：默认档即可识破片假名、谐音、拼音、缩写、拆字、外语等常见规避手段，且合规语境零误杀。**

### 稳定性复测（第 2 轮，同默认档）

同一模型在 temperature=0 下**重复审核仍有波动**：第 2 轮中"你们学校就是个垃圾"和拆字"土立土及"被判为合规。这是大模型的固有特性，无法保证 100% 稳定。建议：

- 把违规处理动作设为 `hide_and_flag`（默认），让管理员复核兜底；
- 对风险高发类别用自定义指令**明确点名**（见第三档示例），可显著降低漏检；
- 若要求更高确定性，可换用判别更稳的模型，或后续扩展"双模型投票"能力。

### 严格档（自定义指令）第 3 轮

应用"档位三：严格模式"自定义指令后复测（同一组 27 个用例）：

- 第 2 轮（默认档）漏检的 **"你们学校就是个垃圾"** 与 **拆字"土立土及"** 均被补抓为违规；
- 合规语境中的 **新闻报道、毒品科普、举报、正常讨论（C1/C2/C3/C5）仍判定为合规**——严格档并非"见敏感词就杀"；
- 但 **"学校食堂的饭太难吃了，简直是垃圾"（针对食物的吐槽）被误判为违规**——这正是严格档"任何贬损表达一律违规"的代价；
- 政治敏感（合成）用例被判为"政治敏感"类别（比默认档的"违反法律法规"更具体）。

**结论**：严格档能显著降低漏检（把默认档的波动性缺口补上），但会明显提高误杀率。建议：
- 高风险社区搭配默认动作 `hide_and_flag` 使用（误杀可由管理员一键恢复，作者也会收到通知）；
- 若误杀过多，在严格规则里补充豁免条款（如"对食物、物品、机构职能的批评不算攻击"）。
